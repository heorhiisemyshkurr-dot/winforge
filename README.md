# WinForge — настройка и оптимизация Windows

Отдельная программа рядом с BOB's Opti: тот настраивает игру и систему под
игру, эта — саму Windows. Внешний вид, приватность, автозагрузка,
производительность. Windows, Tauri 2, интерфейс без сборщика.

```powershell
cargo build --release --manifest-path winforge/Cargo.toml
```

Получается один `winforge.exe`. `npm` здесь не нужен совсем — и это главное
отличие сборки от основного приложения, где `cargo build` без `tauri build`
даёт exe без вшитого фронтенда. Интерфейс лежит в `ui/` тремя обычными
файлами, вшивает их `tauri-build`, собирать нечего и ломаться нечему.

## Почему интерфейс без React и без сборщика

Потому что здесь нечего собирать. Весь интерфейс — это списки с
переключателями: ни шейдеров, ни анимаций, ни графиков. React, Tailwind и
Vite принесли бы вторую `node_modules`, второй `package.json` и ещё один
способ сломать сборку — ради разметки, которая укладывается в 600 строк на
`createElement`.

Разметка собирается именно через `createElement`, а не склейкой строк в
`innerHTML`, и это не вкусовщина. Половина того, что программа показывает,
пришла из реестра и из списка пакетов: пути, имена программ, командные
строки автозагрузки. Склей такое в HTML — и чужая строка в чужой
автозагрузке станет кодом внутри окна, которое ходит в реестр с правами
администратора.

## Три правила каталога

**Нет отката — нет настройки.** Действие описано данными, а не кодом:
одно и то же описание умеет сказать, как сейчас в системе, снять прежнее
значение, применить новое и вернуть ровно то, что было. Четыре функции на
каждую настройку разошлись бы, и откат начал бы возвращать «наверное, было
так». Исключение одно — удаление встроенных приложений; оно помечено
необратимым, и это проверяется тестом.

**Сказано, когда подействует.** Самая частая жалоба на любой оптимизатор —
«нажал, ничего не изменилось». Половина настроек внешнего вида читается
Проводником при запуске, часть системой — при входе, часть — при загрузке.
Поэтому у каждой настройки есть поле `effect`, а в окне появляется кнопка
«Перезапустить Проводник». Без этого человек нажимает второй раз — уже
обратно.

**Сказано, чем платишь.** Поле `detail` обязательно, и тест требует от него
осмысленной длины. «Отключить службу поиска Windows» без слов «поиск по
файлам перестанет работать» — это не настройка, а ловушка.

## Из чего состоит

| Файл | За что отвечает |
|---|---|
| `src/sys.rs` | запуск средств Windows, кодовая страница консоли, права |
| `src/reg.rs` | реестр: чтение, запись, сравнение значений |
| `src/action.rs` | действие: состояние, снимок, применение, откат |
| `src/catalog.rs` | вшитый каталог и готовые наборы |
| `src/store.rs` | что применено сейчас и чем это вернуть |
| `src/scan.rs` | автозагрузка, приложения, железо, точка восстановления |
| `src/main.rs` | команды для интерфейса |
| `catalog/*.json` | сам каталог: по файлу на раздел |
| `ui/` | интерфейс: `index.html`, `app.css`, `app.js` |

Программа ничего не делает своими руками: ни драйверов, ни правки системных
файлов. Всё умеет сама Windows — `reg`, `sc`, `powercfg`, `schtasks`,
`powershell`. У каждого из них есть обратная команда, а значит есть откат; и
любое изменение можно повторить руками и проверить, что оно сделало.

## Каталог лежит открыто

В отличие от BOB's Opti, где каталог приходит с сервера по живому ключу,
здесь он вшит в exe из `catalog/*.json` и виден любому. Это сознательно:
содержимое каталога — не секрет, а предмет проверки. В окне у каждой
настройки есть ссылка «что именно меняется», и она показывает ровно ту
ветку реестра или ту команду, которая пойдёт в систему.

## Что уже проверено на живой машине

Разбор вывода системных средств сверен с настоящими ответами Windows 11
сборки 26300 с украинским языком интерфейса — и в двух местах оказался не
таким, как в советах из интернета:

**Схемы питания размножаются.** `powercfg /duplicatescheme` создаёт **новую**
копию при каждом вызове. На проверочной машине нашлось больше шестидесяти
схем «Максимальна продуктивність» — следы чужих программ, которые звали эту
команду на каждое нажатие. Поэтому WinForge сначала смотрит `powercfg /list`
и размножает схему только если её там нет. А состояние сравнивает ещё и по
названию схемы: активной может быть чужая копия с другим GUID, и писать
«выключено» про неё было бы неправдой.

**Задания планировщика переименовывают.** `Microsoft Compatibility Appraiser`
на сборке 26300 зовётся `…Appraiser Exp`, а `ProgramDataUpdater` исчез
вовсе. Поэтому у задания в каталоге список имён, а программа выключает то,
которое есть в системе, — как `games.rs` в BOB's Opti перебирает имена
процессов.

**Повышение прав у обычной учётной записи меняет пользователя.** Если
человек работает без прав администратора, Windows на согласии UAC не
повышает его, а **переходит на администраторскую учётную запись**. У того
процесса `HKCU` уже чужой: половина набора уехала в профиль администратора,
программа сказала «применено», а у человека не поменялось ничего. Список для
откатa тоже лёг в чужую папку — то есть обещание «вернуть как было»
оказалось бы пустым. Поэтому при повышении прав программа передаёт себе SID
того, кто её запустил, и пишет пользовательские значения не в `HKCU`, а в
`HKU\<SID>`; туда же, в папку запустившего, идёт и список применённого
(`--as-user` и `--store`).

**Параметр схемы питания может быть заблокирован.** На Ryzen с CPPC под
схемой «Максимальная производительность» запрет парковки ядер не ставится
никаким значением: `powercfg` сообщает границы «от 0x32 до 0x00», то есть
бессмысленные, и отвечает «value is malformed, or is not within the range».
Программа это распознаёт и говорит словами, что параметр заблокирован самой
схемой — а не пересказывает английскую строку. «Агрессивного режима
ускорения» в этой схеме не существует вовсе, и это тоже сказано прямо.

Подписи в выводе `powercfg`, `sc` и `schtasks` переведены на язык системы, а
константы (`AUTO_START`, `DISABLED`, `RUNNING`) и числа — нет. Поэтому разбор
цепляется за них, а состояние заданий читается через PowerShell `.State`, а
не через `schtasks`. Тесты на русский и украинский вывод лежат рядом с
разбором.

## Чего в программе нет и не будет

Разгона, правки загрузчика, отключения Defender, удаления компонентов
Windows. Не потому, что это сложно, а потому, что это нельзя вернуть кнопкой
«как было» — а всё остальное в программе можно. Удаление встроенных
приложений — единственное исключение, и оно требует двух нажатий и написано
красным.

Температур и частот в разделе «Производительность» тоже нет: их не отдаёт ни
одно средство самой Windows, для них нужен драйвер вроде
LibreHardwareMonitor. Показывать «температуру», которой программа не знает,
хуже, чем не показывать ничего.

## Известные пределы

**«Уже стоит».** Если настройка включена не программой, её переключатель
показан включённым, но снять его нельзя: прежнего значения программа не
знает, а подставить своё представление о «значении по умолчанию» — это не
откат, а ещё одно изменение. Для взаимоисключающих групп (тёмная и светлая
тема, положение значков, схемы питания) выход есть — выбрать другой пункт
группы. Чтобы снять это ограничение у остальных, в каталог надо добавить
поле со значением по умолчанию; пока его нет.

**Обои не запоминаются.** Прежний путь показан рядом с полем — скопируйте
его, если захотите вернуть. В списке применённого обоев нет: это
единственное действие в программе, которое идёт мимо снимков.

**Запись автозагрузки отключается отметкой диспетчера задач** — той же
двоичной отметкой в `StartupApproved`, что ставит сам диспетчер. Для записей
из ветки «все пользователи» отметка ставится для текущего пользователя:
так же делает диспетчер задач, и так она не требует прав администратора.

## Командная строка

Нужна затем, что большая часть каталога требует прав администратора, а
повысить их можно только при создании процесса: с окном это «перезапустите
программу», без окна — одно согласие Windows на весь набор.

```powershell
winforge.exe apply rust_fps          # набор целиком
winforge.exe apply hags_on nagle_off # поимённо
winforge.exe revert hags_on          # снять одну
winforge.exe revert-all              # снять всё, что программа сделала
winforge.exe status                  # как сейчас настроена система
winforge.exe restore-point           # точка восстановления
```

Отчёт пишется в `%LOCALAPPDATA%\WinForge\last-run.txt`, а не в консоль:
программа помечена как оконная, и её вывод в терминале никто не увидит.
Файл с отметкой UTF-8 в начале — иначе Windows PowerShell и «Блокнот»
читают его кракозябрами.

Наборы: `rust_fps` (под Rust), `max_fps`, `quiet_system`, `clean_look`.

## Тесты

```powershell
cd winforge; cargo test
```

Сорок две проверки, и ни одна не лезет в живую систему: проверяется
разбор вывода (включая вывод на русском и украинском), сравнение значений
реестра и сам каталог — уникальность идентификаторов, наличие объяснений,
совпадение флага прав с ветками HKLM, наличие обратной команды у каждой
прямой, и то, что ни один готовый набор не тянет за собой необратимое.

## Права администратора

Программа запускается без них и половину каталога применяет как есть: всё,
что лежит в HKCU. Для служб, заданий, питания и HKLM нужны права — наверху
окна появляется кнопка перезапуска. Повысить права у живого процесса нельзя,
Windows выдаёт их только при создании процесса, поэтому кнопка именно
перезапускает программу, а не «включает режим администратора».
